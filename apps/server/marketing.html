Pipeline

Deterministic rules first. LLM second.

Every review runs the same order of operations, so results are reproducible and cheap. The model only sees hunks the rules couldn’t already judge — with secrets redacted before anything leaves your queue.

01 · webhook

PR opened or pushed

Signature-verified webhook enqueues one job per head_sha. Duplicate deliveries and rapid push bursts coalesce into a single review — never two bots racing on one PR.

02 · rules

Static checks run free

Doc-audit and Semgrep sweep the changed paths first. Deterministic findings cost nothing, never hallucinate, and carry a stable rule_id for exact dedup.

03 · LLM review

Model reads only the diff

Changed hunks plus your rules file go to the model; structured JSON comes back. Findings below your confidence threshold are dropped before anyone sees them.

04 · dedup

Fingerprints, not vibes

Every finding hashes to a fingerprint. If it’s already open on the PR, it is not posted again — push twelve times, hear about each issue once.

05 · post

One review, capped

Inline comments for P1/P2 on the exact diff line, a summary for the rest, hard-capped at 8 comments per PR (yours to configure).

06 · verify

Fixes acknowledged

On the next push, prior findings are re-checked against HEAD. Resolved ones get a “Fixed on sha” reply — the thread closes itself.

Re-review

Get zero repeated nits.

Most review bots re-read the whole diff on every push and re-post everything they find. Orvex Review diffs only last_sha..head_sha, re-checks its own prior findings on HEAD, and speaks only when something is new.

Control

Your repo sets the rules.

  • ✓Per-repo config in git — reviewed and versioned like everything else.
  • ✓Label to silence — add review-bot:ignore and the bot skips the PR entirely.
  • ✓Secrets never leave — key patterns and .env content are redacted from the diff before the model sees it.
  • ✓Suggests, never gates — the check run is informational; your CI still decides what merges.
  • ✓Drafts & bots skipped — draft PRs and dependabot don’t burn your budget.

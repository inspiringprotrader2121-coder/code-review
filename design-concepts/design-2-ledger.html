How it works

Three layers of review, in the order that saves you money.

Cheap exact checks run before a single AI token is spent. Then the ensemble weighs in. Then Orvex proves it — by running the code, not just reading the diff.

01

Deterministic rules first

Exact, repeatable checks run before any model — catching the obvious the cheap way, so AI budget goes to the hard bugs.

rules → only then AI

Up to three independent models review one PR. Different models catch different bugs — the merged result is the whole point.

3 models · one verdict

Config as code

Your repo sets the rules.

One file, checked into your repository. No dashboards to babysit — the review policy lives with the code and moves with your branches.

  • Pick how many models weigh in per PR.
  • Turn sandbox execution on for the paths that matter.
  • Cap the comment budget so reviews stay lean.
.orvex-review.yml yaml 
# Orvex review policy — lives in your repoversion: 1review:  rules_first: true       # cheap checks before AI  models: 3              # ensemble size (1–3)  max_comments: 8        # signal, not noise  repeat_findings: neverrun_code:  enabled: true         # sandbox execution  paths:    - "src/payments/**"    - "src/auth/**"on_demand: "@orvex deep"  # heavier pass
